# Bendmaple 1.0 TEST
Native Java/Canvas Android 8+ Sashikazune distance-to-bend puzzle.

Fence the full grid into L-shaped rooms. Each arm is one cell wide and extends at least one cell past the bend. Each number counts cells from itself to its room bend, counting both endpoints, so 1 must be at a bend. A room may have zero, one, two or three clues. No extra internal wall may split connected cells of the same room. Twelve distinct 4x3 clue boards each have one unique partition.

Saved bend palette and cell guides, GG007 icon/menu/site/privacy, unlimited undo/reset. Offline, no ads, analytics, account or requested permissions. Settings and completed-puzzle marks stay on device. External studio link opens browser.

Independent Python exact cover enumerates all 20 L tilings; a Java oracle uses the original shape cells, bend positions and explicit path lists. It agrees with production floodfill, knee geometry and distance checks on all 131072 border masks per board. Unique solution, bounds, solve, undo and replay pass. Adapter navigation, saved settings, privacy, edge taps, next, levels and persistence pass. Actual drawing pixels inspected, not phone screenshots. Phone runtime, performance and browser handoff QA incomplete. Signed TEST only, not final or Play published.

Current 803-entry registry, 115 partial recovered README records and exact Quiltfen cumulative stage found no Sashikazune match. Shared L-room fence interaction with Bendwillow is disclosed: that Sashigane edition puts a total room-area number at the knee. Here clues can be anywhere on either arm and constrain their own path length to the bend, not room area. Up to three clues can constrain one L, including clues on opposite arms. This changes the constraint algorithm and deduction problem rather than only names or colors. Known Sashikazune genre, not a global invention. Partial recovered corpus, not ALL-local. Rules: https://www.cross-plus-a.com/html/cros7sskz.htm and https://www.janko.at/Raetsel/Sashikazune/index.htm .
